# tools/qa — инструменты проверки «глазами» и мутациями

Всё запускается из корня проекта. Результаты — в `tools/qa/out/` (в git не попадает).

## 1. Скриншоты программы в браузере — `run.mjs`

Headless Chrome (`C:/Program Files/Google/Chrome/Application/chrome.exe`) управляется через DevTools
Protocol, программа отдаётся своим node-сервером на порту 8431 (python `http.server` не выдерживает
одновременной загрузки десятков js и роняет часть файлов).

```
node tools/qa/run.mjs          # полный сценарий показа → tools/qa/out/shots/01…17-*.png
node tools/qa/run.mjs vat      # общая часть + хвост tails/vat.txt
```

**Общая часть** (`shoot.mjs`): две комнаты — «Кухня (немецкий)» и «Гостиная (итальянский)», пост Neve Up
на 4 модуля собирается в гостиной и ставится в кухню (накладка меняется на немецкую 09664.01).
На каждом кадре красной рамкой обведено, куда нажимать (`shot(имя, [селекторы])`).

**Хвосты** (`tails/*.txt`) — код, вставляемый вместо сцен «отказ … КП», когда нужен только свой кусок:

| хвост | что проверяет |
|---|---|
| `vat`   | три режима НДС: панель + текст и снимок КП |
| `num`   | автономер КП EPG-ГГГГ-NNNN: первая печать, повтор, ручной, после перезагрузки |
| `inst`  | лист монтажника: «Взрыв-схема» и «Общая сборка» |
| `inst2` | набор столбцов «Для строителя» не сбрасывает «Общую сборку» |
| `disc`  | личная скидка позиции: поле в спецификации, пометка и итог в КП (HTML → out/kp-disc.html) |

Приём для документов: КП и лист монтажника открываются через `window.open` — в хвосте его
подменяют объектом, который копит `document.write` в `window.__kp`; дальше HTML можно разобрать
или отрисовать в новой вкладке (`Page.setDocumentContent`) и снять.

Грабли: внутри шаблонных строк `ev(\`…\`)` экранирование двойное — регулярки и `\n` лучше не писать,
а разбирать HTML уже в node (как в хвосте `disc`). Bash съедает обратные кавычки в `node -e "…"` —
скрипты писать файлами.

## 2. Презентация из скриншотов — `build-deck.py`

`python tools/qa/build-deck.py` — собирает `docs/к-встрече-2026-09-24.pptx` из `out/shots`
(python-pptx + Pillow). Под новую встречу — поменять слайды и имя файла внутри.

## 3. Мутации в изолированной копии — `mutate.cjs`

```
node tools/qa/mutate.cjs tools/qa/mutations/example-status.json "tests/statusCountsWiring.test.js"
```

Копирует проект во временную папку (node_modules — ссылкой, снимается явно перед удалением), считает
базовый fail, по очереди вносит каждую мутацию, прогоняет тесты и откатывает. Рабочее дерево не
трогается. Формат файла мутаций — см. `mutations/example-status.json`; `from` должен встречаться
в файле ровно один раз. Правило проекта: ВСЕ мутации из отчёта исполнителя перепроверяются лично.
