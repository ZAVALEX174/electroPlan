# tools/ — пересборка каталога VIMAR из номенклатуры и прайса

Скрипты регенерируют каталог приложения из **файла номенклатуры заказчика**
(состав + атрибуты) и **прайса VIMAR** (актуальные цены):

- `js/catalog-vimar.js` (`window.EP_VIMAR_CATALOG`) — состав каталога;
- `js/catalog-vimar-attrs.js` (`window.EP_VIMAR_ATTRS`) — признаки автосостава
  поста (стандарт накладки/суппорта, тип стены/форма/стандарты коробки).

## Быстрый старт

```bash
npm install          # один раз: ставит dev-зависимость xlsx (SheetJS)
npm run build:catalog   # состав + цены → js/catalog-vimar.js
npm run build:attrs     # признаки поста → js/catalog-vimar-attrs.js
```

Оба скрипта читают один и тот же файл номенклатуры через общий модуль
[`lib/nomenclature.mjs`](lib/nomenclature.mjs) (единый источник классификации —
не разъедется между файлами). Порядок запуска не важен.

## Как это устроено

**Состав и атрибуты** каталога берутся из номенклатуры в явном виде — это заменило
прежнюю курацию по прайсу (`data/catalog-curation.json`) и эвристику по названию:

| Атрибут | Колонка номенклатуры |
|---------|----------------------|
| `kind` (mechanism/frame/socket_box/support) | Функциональная группа |
| `series` (массив) | Серия |
| `moduleSpan` / `slotCount` / box `modules` | Размер в модулях |
| `standard` (IT/DE/BOTH) | Монтажный стандарт |
| `wallType` (solid/hollow) | Тип стены |
| `properties.frameLevels` | Количество уровней в рамке |
| `properties.boxModularity` | Модульность для коробки |
| `categoryId`, `icon` механизма | по названию через [`lib/classify.mjs`](lib/classify.mjs) |

**Цена** берётся из прайса по артикулу (цены прайса свежее — в номенклатуре они
устаревшие). Если артикула в прайсе нет (новинки) — цена из номенклатуры,
`properties.priceSource = "nomenclature"`.

**ID стабильны**: сопоставляются по артикулу через
[`data/catalog-ids.json`](data/catalog-ids.json). Сид снят из прежнего каталога —
пересекающиеся коды сохраняют id, старые сохранённые проекты не теряют ссылки.
Новым артикулам выдаётся id из диапазона `200000+` и **дописывается в тот же файл**;
после первого прогона карта полна, повторный запуск даёт тот же результат.

> Колонки «статус/Активный» в номенклатуре **нет** — фильтровать по активности
> нечем; в каталог идут все строки с артикулом. Серия IDEA исключается по флагу
> `excludeSeries` (в текущем файле её и нет).

## Монтажные окна накладок → `js/catalog-vimar-openings.js`

`detect-openings.mjs` снимает РЕАЛЬНУЮ геометрию монтажных окон с **детального фото**
накладки, чтобы сборка поста (`js/postImage.js`) рисовала клавиши точно в окна, а не
по догадке об аспекте.

```bash
npm run build:openings          # окна всех накладок → js/catalog-vimar-openings.js
npm run build:openings -- --bases 09673,09664,09666   # только эти базы (быстрая проверка)
npm run build:openings -- --limit 10                  # первые 10 баз
```

- **Декодирование JPEG** — чистым JS через devDependency [`jimp`](https://www.npmjs.com/package/jimp)
  (в браузерный рантайм не идёт, как и `xlsx`).
- **Алгоритм.** Окно — сквозная дыра, залитая на фото чистым белым (`min(R,G,B) ≥ 250`)
  и не связанная с внешним фоном: заливкой от краёв кадра отсекаем фон, оставшиеся связные
  компоненты белого — окна; их bbox переводим в проценты от фото. Блики по верхней/нижней
  кромке отбрасываем (короткие пятна у канта; окна одного ряда ~одной высоты, в средней
  части кадра).
- **Группировка по форме.** Геометрия у цветовых вариантов одна (`09673.01`/`09673.04` →
  база `09673`) — качаем и считаем **одну** фотографию на базу, результат применяется ко всем
  цветам. Ключ файла — база артикула.
- **Сеть.** Последовательно, с таймаутом и повтором; скачанное кэшируется в `.tmp-openings/`
  (маска `.tmp-*` в `.gitignore`). Повторный прогон детерминирован и сети не касается.
  Скачивание и хранение изображений VIMAR согласовано с заказчиком.
- **Подключение к приложению.** `js/data.js` подмешивает окна к накладкам по базе артикула
  в поля `mountRect` (одно окно, итальянская) / `mountRects` (несколько, немецкая); их читают
  `EPCatalog.frameOpening`/`frameOpenings`. Нет измерений (фото не разобралось / товар не из
  VIMAR) — `postImage` падает на фолбэк `splitOpening`.

Отчёт после прогона: сколько баз обработано, сколько окон найдено, у каких баз число окон
**не совпало** с ожидаемым по названию (посмотреть глазами) и у каких фото не удалось
скачать/разобрать.

## Лицевая часть механизмов → `js/catalog-vimar-faces.js`

`detect-faces.mjs` снимает геометрию ЛИЦА механизма с детального фото, чтобы в ячейку модуля
легло ровно лицо — без монтажных лапок, полей кадра и комплектных аксессуаров.

```bash
npm run build:faces                                   # все механизмы с фото
npm run build:faces -- --codes 09001,09005.2.CM,14346 # только эти артикулы
npm run build:faces -- --limit 20                     # первые 20 (быстрая проверка)
```

- **Почему считается точно.** Механизмы сняты фронтально и единообразно, а лицо модуля VIMAR
  имеет физическое отношение ширина/высота = `span × 22,5/45` (модуль 22,5×45 мм): 1М → 0.5,
  2М → 1.0, 3М → 1.5. По ширине предмета и числу модулей высота лица вычисляется однозначно,
  лапки сверху/снизу отсекаются центрированием, `TRIM` срезает светлую кромку рамки механизма.
- **Кадр режется на предметы.** У части позиций рядом с модулем лежит комплектный аксессуар
  (косичка-переходник HDMI, отдельный коннектор RJ45). Выбирается предмет с пропорцией модуля,
  аксессуар остаётся за кадром. Провод — тонкая горизонтальная перемычка, обычной связностью
  не рвётся, поэтому предметы разделяются вертикальным размыканием (`VOPEN_FRACTION`).
- **Составные позиции** (пара клавиш EnOcean — в кадре два отдельных предмета при `span > 1`)
  в файл НЕ пишутся: растягивать их на два модуля было бы враньём, позиция уходит на
  нарисованную клавишу-фолбэк.
- **Ключ — полный артикул, а не база.** У механизмов суффикс после точки часто кодирует
  ИСПОЛНЕНИЕ, а не цвет (`09001.0.250` — 1 модуль, `09001.2.CM` — 2 модуля: одна база, разный
  span и разное фото), и у каждого цвета своя фотография. Поэтому считаем по каждому артикулу;
  загрузки идут последовательно с паузой, кэш в `.tmp-faces/`.
- **Чистая логика** (маска, разбиение на компоненты, выбор предмета, решение «фото или фолбэк»)
  вынесена в [`lib/faces.mjs`](lib/faces.mjs) и покрыта тестами `tests/faces.test.js`.
- **Подключение к приложению.** `js/data.js` подмешивает лицо механизму в поле `faceRect`,
  читает `EPCatalog.moduleFace`, рисует `js/postImage.js` CSS-спрайтом (без JS — уходит в печать).

Отчёт после прогона: сколько лиц посчитано, какие позиции ушли в фолбэк как составные и какие
помечены подозрительными (единственный предмет, но пропорция не сошлась) — последние смотреть глазами.

Порядок добавления новой линейки целиком — в [`docs/добавление-новой-линейки.md`](../docs/добавление-новой-линейки.md).

## Входные файлы (пути по умолчанию — от корня репозитория `electro/`)

| Флаг | По умолчанию | Что это |
|------|--------------|---------|
| `--nom` | `Номенклатура новая.xls` | номенклатура (состав + атрибуты) |
| `--xls` | `Прайс VIMAR Евро 01.07.26 (2) (2).xls` | прайс VIMAR (цены) |
| `--images` | `outputs/db_price_import_20260723/vimar-ru-image-index.json` | картинки vimar.ru (приоритет) |
| `--images-official` | `outputs/db_price_import_20260723/vimar-image-index.json` | картинки междунар. каталога |
| `--ids` | `tools/data/catalog-ids.json` | карта стабильных id |
| `--out` | `js/catalog-vimar.js` / `js/catalog-vimar-attrs.js` | результат |

Пример с новой номенклатурой:

```bash
npm run build:catalog -- --nom "../Номенклатура 2027.xls"
```

Индексы картинок — ранее собранные артефакты (скрейпинг vimar.ru). Их регенерация
выходит за рамки конвертера. `data/catalog-curation.json`, `price-parsed.csv`,
`compat-external.json`, `box-wall-type.json` больше конвертером **не используются** —
оставлены как исторический артефакт прежнего пайплайна.

## Замечание по зависимости

`xlsx` (SheetJS 0.18.5) имеет известную advisory (prototype pollution / ReDoS).
Здесь это **build-time тул**, читающий доверенные локальные `.xls`, и в браузерный
рантайм он **не попадает** — риск неприменим. При желании обновиться — ставьте
свежий SheetJS с их CDN (в публичном npm застряла 0.18.5).
