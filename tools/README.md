# tools/ — пересборка каталога VIMAR из прайса

Скрипты для регенерации `js/catalog-vimar.js` (`window.EP_VIMAR_CATALOG`) из
официального прайса VIMAR. Заменяют разовый скрипт
`outputs/db_price_import_20260723/build_db_price.mjs`, который был завязан на
внутренний пакет `@oai/artifact-tool` (песочница Codex) и не запускался вне неё.

## Быстрый старт

```bash
npm install          # один раз: ставит dev-зависимость xlsx (SheetJS)
npm run build:catalog
```

Скрипт читает прайс, обновляет цены/наименования/картинки и перезаписывает
`js/catalog-vimar.js`. В конце печатает сводку: сколько позиций собрано, какие
цены изменились, каких кодов больше нет в прайсе.

## Как это устроено

Состав каталога — **кураторское решение**: из 7000+ строк прайса на плане
реально расставляются лишь ~400 ЭУИ (механизмы, рамки, подрозетники). Этот отбор
и стабильные атрибуты (тип, категория, иконка, серия, геометрия рамок
`slotCount`/`mountRect`, ширина механизма `moduleSpan`) зафиксированы в
[`data/catalog-curation.json`](data/catalog-curation.json).

Конвертер **не переугадывает состав эвристикой** каждый раз, а берёт курацию как
основу и обновляет из прайса только изменчивые поля:

| Поле | Источник |
|------|----------|
| `name`, `price`, `properties.packQty` | прайс (`.xls`) |
| `id`, `properties.sourceRow` | номер строки в прайсе (`100000 + sourceRow`) |
| `previewImageUrl`, `imageUrl`, `productPageUrl`, `properties.imageSource` | индекс картинок |
| `kind`, `categoryId`, `icon`, `series`, `slotCount`, `mountRect`, `moduleSpan` | курация (сохраняются как есть) |

Поэтому при **обновлении прайса** (PLAN.md 1.7) достаточно подложить свежий
`.xls` и пересобрать — цены обновятся, а изменения и пропавшие позиции попадут в
отчёт. **Расширение состава** (новые позиции, разбор `check_kind`) — правится
`data/catalog-curation.json` (Фаза 2); в помощь — эвристика
[`lib/classify.mjs`](lib/classify.mjs), перенесённая из прежнего скрипта.

## Входные файлы (пути по умолчанию — от корня репозитория `electro/`)

| Флаг | По умолчанию | Что это |
|------|--------------|---------|
| `--xls` | `Прайс VIMAR Евро 01.07.26 (2) (2).xls` | прайс VIMAR |
| `--images` | `outputs/db_price_import_20260723/vimar-ru-image-index.json` | картинки vimar.ru (приоритет) |
| `--images-official` | `outputs/db_price_import_20260723/vimar-image-index.json` | картинки междунар. каталога |
| `--spans` | `outputs/catalog_dropdown_import_20260723/vimar-module-spans.json` | ширина механизмов в модулях |
| `--curation` | `tools/data/catalog-curation.json` | кураторский отбор |
| `--out` | `js/catalog-vimar.js` | результат |

Пример с новым прайсом:

```bash
npm run build:catalog -- --xls "../Прайс VIMAR 2027.xls"
```

Индексы картинок и `module-spans` — это ранее собранные артефакты (скрейпинг
vimar.ru и разбор официальных каталогов). Их регенерация выходит за рамки
парсера прайса и делается отдельными скриптами в `outputs/`.

## Замечание по зависимости

`xlsx` (SheetJS 0.18.5) имеет известную advisory (prototype pollution / ReDoS).
Здесь это **build-time тул**, читающий доверенный локальный файл прайса, и в
браузерный рантайм приложения он **не попадает** — риск неприменим. При желании
обновиться — ставьте свежий SheetJS с их CDN (в публичном npm застряла 0.18.5).
