## Текущий этап работы
> **Сейчас проект в стадии вёрстки/прототипа: чистые HTML, CSS, JS** (пока без
> PHP и без ядра Битрикса). Пишем фронтенд так, чтобы его было легко перенести
> в шаблон компонента/страницы Битрикса на следующем этапе:
> - размечаем блоки по-компонентно, готовые к превращению в `bitrix:*` компоненты
>   и их шаблоны (`template.php` + `style.css`/`script.js`);
> - не завязываемся на конкретные пути и абсолютные URL — они изменятся при
>   интеграции (`SITE_TEMPLATE_PATH`, `BX.ready`, ассеты через `Asset`);
> - динамические данные держим отдельно от разметки (заглушки/JSON), чтобы потом
>   заменить их выводом из инфоблоков без переписывания структуры.
>
> Когда дойдём до интеграции — целевая платформа ниже; тогда же включаются
> PHP-хуки (`php -l`) и сабагент `bitrix-reviewer`.

## Структура — где что лежит
- `/bitrix/` — **ядро платформы, только для чтения**. Правки сюда заблокированы
  технически (`.claude/settings.json`, `.claude/hooks/protect-core.sh`) — обновление
  платформы всё равно их сотрёт.
- `/local/` — весь наш код, все правки только здесь:
  - `/local/components/<namespace>/` — кастомные компоненты
  - `/local/modules/` — кастомные модули (`vendor.module`)
  - `/local/php_interface/init.php` — обработчики событий, автозагрузка
  - `/local/templates/<имя>/` — шаблон(ы) сайта
- `/upload/` — пользовательские файлы, не версионируется

## Конвенции кода
- БД — только через D7 ORM (`Bitrix\Main\...\Table`) или
  `Bitrix\Main\Application::getConnection()`; никогда — конкатенация строк в SQL
- Вывод — только через `htmlspecialcharsbx()`; `$_REQUEST`/`$_GET`/`$_POST`
  не идут в HTML напрямую
- Namespace кастомного кода: `<Vendor\...>`
- Стиль кода: `<PSR-12 / свой стандарт>`
- Новый функционал — компонентом или модулем в `/local/`, не правками ядра
  и не вставками в шаблон "на скорую руку"
