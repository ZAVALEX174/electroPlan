# Интеграция ElectroPlan с Битрикс

Сейчас рабочий продукт — статический HTML/JS-прототип. Перед серверной работой проверь, доступен ли реальный Битрикс, его редакция, версия PHP и схема каталога. Если сервера нет, готовь код и контракт отдельно и не называй проверку Node-тестов проверкой на Битрикс.

## Где искать проектные решения

- [План](../../../PLAN.md): целевая платформа, каталог и интеграция (разделы 0, 6).
- [Задел модуля](../../../local/README.md): `centrsvet.electroplan`, `Centrsvet\Electroplan`, компонент и адаптер данных. Сверяй с фактическим кодом `local/` перед изменениями.
- [Карта кода](../../../.claude/project-map.md): навигация по прототипу; номера строк исторические, проверяй их в файлах.
- [Справочник Claude по Битрикс](../../../.claude/skills/1c-bitrix/SKILL.md) и его `references/`: читай только нужную тему (D7, инфоблоки, компоненты, фронтенд, магазин, интеграции, безопасность). Это вспомогательные заметки, не источник актуальности API; спорные сигнатуры сверяй с официальной документацией установленной версии.

`bitrix-map/SKILL.md` сейчас шаблон с вымышленными ID. Не используй его как карту реальных инфоблоков или Highload-блоков. Ищи ID в доступной конфигурации или на сервере; если доступа нет, оставляй их параметрами.

## Границы реализации

- Кастомный PHP-код размещай в `local/`. Ядро `/bitrix/` не меняй; конфиги и учётные данные не публикуй.
- Используй уже заведённый `DataService` как шов между прототипом и серверным каталогом. Сохраняй формат товара и стабильность ссылок сохранённых проектов.
- При загрузке прайса разделяй проверку, черновик и публикацию общей версии; прежние проекты должны читать закреплённую версию каталога.
- Проверяй права на запись и защиту запросов в серверном обработчике. Публичная страница не хранит ключ публикации.
- Для затронутого PHP запускай `php -l`, если PHP установлен; для фронтенда запускай относящиеся к правке тесты. Отдельно сообщай, что без рабочего Битрикс нельзя проверить его API и права в рантайме.
