# К9: загрузка прайса в браузере с переходом на сервер

Решение, предложенное владельцем 15.11.2026: выполнять К9(2)/(3) сейчас без сервера, хранить
загруженный каталог в браузере и оставить возможность сменить хранилище на серверное.

## Что есть сейчас

- К9(1) готов: шаблон Excel, проверка файла и отчёт в `priceCheckUi.js`.
- `DataService.getProducts()` уже асинхронный: режим `mock` возвращает копию встроенного каталога,
  режим `api` обращается к `/api/products`. Это точка смены хранилища.
- Проект сохраняет посты с ID товаров, но не снимок каталога. Если просто заменить список товаров,
  старый проект может получить другую цену или потерять товар. Поэтому привязка проекта к версии
  каталога нужна до включения импорта.

## Порядок реализации

1. Выделить единый контракт хранилища каталога: получить активную версию, сохранить новую версию,
   переключить активную версию и получить версию проекта. Реализация для браузера — IndexedDB;
   серверная реализация позже подключится через тот же контракт. Встроенный каталог остаётся
   начальной версией для существующих установок.
2. Преобразовывать прошедшие `EPPriceTemplate.check()` строки в товары теми же правилами колонок,
   что у конвертера каталога. Сопоставлять товар по артикулу, сохранять устойчивый ID; показывать
   перед применением числа добавленных, обновлённых и отсутствующих в новом файле позиций.
3. После успешной проверки дать отдельное действие «Применить прайс». Запись новой версии должна
   быть атомарной; ошибка чтения или квоты не меняет активный каталог. Оставить возможность
   вернуть предыдущую версию. Дать выгрузку версии каталога в файл для резервной копии:
   данные браузера пользователь может очистить, а браузер может удалить их при нехватке места.
4. Привязать проект к версии каталога и сохранять данные используемых товаров в файле проекта,
   чтобы перенос файла в другой браузер не менял состав и цены. Старым проектам назначать
   исходную встроенную версию при первом открытии.
5. Для К9(3) использовать то же сохранение версии при добавлении или правке одного механизма
   либо накладки. Проверка обязательных полей — та же, что у импорта.
6. Позже подключить серверный адаптер к `DataService`. Переключение источника включать только
   при доступном сервере и после переноса локальных версий; один проект всегда открывать со
   своей версией каталога.

## Приёмка

- Новый прайс меняет расчёты новых проектов; старый проект и его экспорт сохраняют прежние
  артикулы, состав и цены.
- Ошибочный файл, повторный импорт и переполнение хранилища не портят активную версию.
- Добавленный механизм/накладка виден в конструкторе и смете после перезагрузки страницы.
- Проект, выгруженный в файл, открывается с тем же составом в другом браузере.
