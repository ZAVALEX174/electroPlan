# План: немецкий стандарт в конструкторе поста

> Постановка владельца проекта 31.07.2026 по скриншоту: «накладка немецкого стандарта
> с разделением по середине, а программа всё равно рисует, будто это единое пространство.
> Нужно, чтобы выбирались эти пространства под накладку».

## Суть проблемы

Накладка `09664.01` называется «Накладка на 4 модуля **(2+2)**» и имеет стандарт DE. Физически
это **два поста по 2 модуля**, разделённые импостом. Конструктор же показывает сплошной ряд
из четырёх ячеек и позволяет заполнять их как единое пространство.

Это расходится и с изделием, и с прямым правилом заказчика (ответы 31.07, п. 2.3):

> «Не все устройства влезают в немецкий стандарт. Только два по 1 модулю и один
> 2 модульный. Да 71мм между осями.»

То есть в немецком посте помещается **либо два одномодульных механизма, либо один
двухмодульный**. Трёхмодульный не влезает в принципе.

## Что нужно сделать

### 1. Разбиение накладки на посты

- у накладки немецкого стандарта определять раскладку постов: `(2+2)` → два поста,
  `(2+2+2)` → три, `(2+2+2+2)` → четыре. Раскладка есть в названии позиции; надёжнее
  добавить её отдельным признаком при сборке каталога, чем разбирать текст в рантайме;
- итальянская накладка остаётся сплошным рядом — там одна коробка на всю сборку и импостов нет.

### 2. Превью показывает разделение

Ячейки группируются по постам, между группами — импост. Пользователь должен видеть на
превью ровно то изделие, которое держит в руках.

### 3. Заполнение — по постам, а не общей суммой

- ёмкость проверяется **для каждого поста отдельно**: 2 модуля;
- механизм шириной 3 модуля в немецкую накладку не предлагается вовсе;
- двухмодульный механизм занимает пост целиком;
- нельзя «размазать» механизм через импост: механизм не может начинаться в одном посте
  и заканчиваться в другом.

Сейчас проверка идёт по суммарной ёмкости, поэтому конструктор разрешает собрать то,
что физически не собирается.

### 4. Нумерация модулей в листе монтажника

Модули нумеруются с указанием поста: «пост 1, модули 1–2», «пост 2, модуль 1». Монтажнику
важно знать, что это две отдельные коробки, а не одна.

Число коробок уже считается верно (по числу постов) — расходится только подача.

## 5. Единое изображение собранного поста — везде одно и то же

Постановка владельца 31.07.2026 по скриншоту библиотеки: «здесь нет получившегося полного
изображения рамки и модулей».

Сейчас собранный пост рисуется **только в конструкторе** (`#postPreview`: изображение
накладки, поверх — модули в её окне). В остальных местах показывается что попало:

| Где | Что сейчас | Что нужно |
|---|---|---|
| Конструктор | собранный пост | оставить |
| Библиотека «Готовые посты» | россыпь иконок механизмов | собранный пост |
| Карточка при наведении на плане | список названий | собранный пост (миниатюра) |
| Раскладка постов в КП | картинка одной накладки | собранный пост |
| Лист монтажника | нет | собранный пост |

**Решение:** вынести отрисовку собранного поста в одну переиспользуемую функцию с
параметром размера (крупный в конструкторе, миниатюра в библиотеке и документах).
Тогда изображение везде одинаковое и не разъедется при правках.

Это же автоматически распространит на все места разделение по постам и импосты из
пунктов 1–3 — сейчас их пришлось бы реализовывать в каждом месте заново.

Для документов (КП, лист монтажника) учесть: изображение уходит в печать, поэтому оно
должно собираться без зависимости от экранных стилей приложения.

## Связанное

- **Двухрядные накладки «4+4»** (166 позиций из 260 восьмимодульных) — та же природа
  проблемы, но разделение по вертикали. Решение владельца по ним пока не принято:
  отложить до двумерной нумерации либо оставить с линейной.
- **Многорядные 14 (7+7) и 21 (7+7+7)** — отложены, из подбора исключены.

## Порядок

1. Признак раскладки постов у накладки (при сборке каталога).
2. Проверка ёмкости по постам + запрет трёхмодульных в немецком.
3. Превью с импостами.
4. Нумерация модулей по постам в листе монтажника.
