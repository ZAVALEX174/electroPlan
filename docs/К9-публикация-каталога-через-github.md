# К9: общий каталог через GitHub Pages

Уточнение владельца 15.11.2026: текущая номенклатура уже новая; более свежего прайса пока нет.
Заказчик проверяет сайт на GitHub Pages. Для текущего этапа общий каталог хранится в репозитории
и публикуется вместе с сайтом. Хранение отдельной копии прайса в браузере не нужно: оно дало бы
владельцу и заказчику разные цены.

## Текущее состояние

- `js/catalog-vimar.js` и `js/catalog-vimar-attrs.js` содержат опубликованный каталог. `js/data.js`
  подмешивает атрибуты; `DataService.getProducts()` отдаёт его приложению.
- К9(1) готов: в программе можно скачать Excel-шаблон и проверить файл. Проверка не меняет каталог.
- Изменение каталога в `main` публикуется на GitHub Pages и после обновления сайта доступно всем.
- К9(2) (загрузка нового прайса через программу) и К9(3) (добавление отдельных изделий) пока не
  реализованы и не нужны для работы с нынешней номенклатурой.

## Когда появится новый прайс

1. Проверить файл тем же правилом, что использует окно «Прайс по шаблону».
2. Собрать каталог и атрибуты с устойчивыми ID по артикулам; показать изменения состава и цен
   перед публикацией. Для публикации через статический сайт требуется коммит в репозиторий:
   публичная страница не должна содержать ключ GitHub с правом записи.
3. До публикации закрепить старые проекты за прежним составом и ценами либо версией каталога:
   сейчас проекты сохраняют ID товаров, а не снимок каталога. Проверить старые проекты и расчёты.
4. Опубликовать проверенные файлы через `git push` в `main` и обновить версии скриптов в `index.html`,
   чтобы браузеры получили новый каталог.

Серверное хранилище можно подключить позже через асинхронный `DataService`. Пока оно не требуется
для общего каталога на GitHub Pages.
