# Б6 — «Этажи»: РЕШЕНИЕ И ФАКТ (04.11)

Источник требования: §1.4 опросника — «этажи нужны». Записано в docs/ОСТАТОК-РАБОТ.md пункт Б6.

## Решение владельца (04.11)

> «ты как-то усложнил про этажи, просто поле ввода какой адрес: улица, дом, квартира и этаж»

Многоэтажные проекты (state.floors, текущий этаж, фильтры рендера) НЕ делаем. Требование закрыто
структурированным адресом объекта: четыре поля вместо одного — улица, дом, квартира/офис, этаж.

## Что сделано (факт)

- `index.html` — в окне «Данные проекта и КП» вместо одного `input#docAddress` четыре поля:
  `docAddrStreet`, `docAddrHouse`, `docAddrFlat`, `docAddrFloor` (комментарий на месте).
- Хранение: `settings.docHeader.addrStreet/addrHouse/addrFlat/addrFloor` (те же DOC_FIELDS в
  `js/app.js` — поля сами пишутся в снимок проекта и читаются обратно, отдельной провязки нет).
- Печатная строка: `docHeader()` (js/app.js) собирает `address` одним правилом —
  «ул. X, д. Y, кв. Z, этаж N», пустые части пропускаются (висячих запятых нет). Документы
  (КП, лист монтажника, экспликация по комнатам) печатают `address` как раньше — их код не менялся.
- Миграция старых проектов: `EPDocRequisites.migrateDocHeader` (js/docRequisites.js) перекладывает
  прежний единый `address` целиком в `addrStreet` (данные не теряются; напечатается «ул. <старый
  адрес целиком>» — приемлемо для старых проектов, новые заполняются структурировано). Старый ключ
  `address` из снимка убирается. Перенос только когда ВСЕ addr* пусты — заполненное не затирается.
  Идемпотентно. Зовётся на обоих путях загрузки (init и restoreProject) из fillDocHeaderInputs.
- Тесты: `tests/docRequisites.test.js` (+5: миграция в addrStreet, не затирает заполненные,
  идемпотентность, сборка строки с пропусками, провязка DOC_FIELDS/формы).
- QA-кадр: `tools/qa/tails/kpsetup.txt` обновлён под новые поля; сценарий `node tools/qa/run.mjs
  kpsetup` зелёный, включая новый контроль «КП содержит собранный адрес «ул. Светлая, д. 1»».
  Кадр полей: tools/qa/out/shots/b6-address-fields.png.

## Почему так

- §7.1: правило сборки строки живёт ОДНИМ местом (docHeader), миграция — ОДНИМ местом
  (migrateDocHeader, рядом с прежней миграцией client→customer).
- Старые файлы проектов открываются без потерь: адрес целиком уезжает в «Улицу».
- vm-стенды: docHeader исполняется в стенде offerNumberWiring — сборка написана литералами,
  без соседних helper'ов (комментарий в коде).
