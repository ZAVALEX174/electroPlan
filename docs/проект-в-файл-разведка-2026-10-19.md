# Проект в файл — разведка (19.10.2026, ep-recon, read-only)

Задача (владелец 19.10, «делаем сразу после К2»): «Скачать проект в файл», «Открыть проект из файла», «Новый проект»
с предупреждением, если текущий не скачан. Заказчик 19.10: «Как мне теперь его сохранить, чтобы потом можно было открыть
именно его? Как его открыть на другом компе? … как потом менять проекты, если хочу оставить в разработке этот и начать новый?»

## Факты (файл:строка на ветке wip/k2-nomenclature, HEAD 441c514)
- Снимок проекта — `projectSnapshot()` js/app.js:2655-2693 (единственный сериализатор): комнаты, посты, стены, вид, масштаб,
  docHeader (с реквизитами заказчика), offerOptions, assemblyView, terms (курс, НДС, наценка, подсветка, валюта), план —
  один PNG data-URL (PDF/DXF растеризуются при импорте; размер не ограничен).
- `persistProject()` 2696: при переполнении localStorage пишет `plan:null, planTooBig:true` → **файл собирать из
  projectSnapshot() напрямую, НЕ из ProjectStore** (иначе потеряется план) — главный край.
- История undo в снимок не входит (решение владельца, app.js:376).
- ВНЕ снимка — бланк человека в `ep_prefs` (js/prefs.js): myRequisites, companyLogo/Signature/Stamp (PNG data-URL),
  companyTerms, offerPresets, frameFacingView, offerCounters (номера КП по годам, docs.js:628); `ep_post_templates`
  (шаблоны постов, data.js:253); `ep_eur_rate` (кэш курса; курс проекта и так в terms).
- Загрузка: `restoreProject()` app.js:2902-3008 читает только `ProjectStore.load()`; полный путь — init() 359-388
  (restoreProject + хвост рендера + `_history.reset(projectSnapshot())`). Хвост не вынесен в функцию. Открытие файла =
  положить объект в ProjectStore + restoreProject + хвост init + сброс истории. Миграции К2 ссылочные (каталог) — сработают.
- Скачивание: образец docs.js:664-675 (Blob → createObjectURL → a[download]). Чтения JSON из файла нет; FileReader для плана
  planImport.js:30-33. Кнопки шапки — index.html:16-21 (.top-actions), обработчик сохранения app.js:3845.
- «С нуля» нет: clearCanvas (3820) не чистит план/настройки; ProjectStore.clear() нигде не вызывается. Автосейв (700 мс)
  пишет в тот же единственный ключ — «открыть» сразу затрёт текущий в браузере.
- Поля version в снимке нет; restoreProject не валидирует чужой/битый JSON.
- Код — в свой модуль (например js/projectFile.js) через attach с ctx {state, projectSnapshot, persistProject,
  restoreProject, toast, _history, …}; в app.js только подключение (замер строк). Тестовые стенды стабят ProjectStore.load —
  не ломать сигнатуру restoreProject.

## Фраза результата — УТВЕРЖДЕНА владельцем 19.10 («устраивают твои предложения по поводу след этапа»)
В шапке программы три кнопки: «Скачать проект» сохраняет файл проекта на компьютер; «Открыть проект» открывает любой такой
файл — на этом или другом компьютере, — и проект выглядит точно так же, с планом, постами и ценами; «Новый проект»
начинает чистый проект и сначала предупреждает, если текущий не скачан.

## Вопросы владельцу (меняют то, что видно)
1. Ехать ли в файле бланку человека (реквизиты исполнителя, логотип, подпись, печать, условия, шаблоны постов)?
2. Номер КП (offerCounters) на другом компьютере свой — возможен повтор.
3. «Не скачан» = изменён после последнего скачивания или «ни разу не скачивали»?
4. «Новый проект» стирает текущий из браузера (после предупреждения); бланк человека остаётся?
5. Файл от более новой версии программы — открывать с предупреждением или отказывать?
