# Стартовый комплект Claude Code для 1С-Битрикс

Настраивает Claude Code под разработку на 1С-Битрикс (Управление сайтом /
Битрикс24): защищает ядро платформы, автоматически проверяет синтаксис PHP,
добавляет сабагента-ревьюера и место для хранения карты проекта.

## Что внутри
- `CLAUDE.md` — память проекта, читается в начале каждой сессии
- `.claude/settings.json` — права доступа и подключение хуков
- `.claude/hooks/protect-core.sh` — блокирует правки `/bitrix/` и файлов с секретами
- `.claude/hooks/php-lint.sh` — проверяет `php -l` сразу после каждой правки `.php`
- `.claude/hooks/verify-before-stop.sh` — не даёт Claude закончить ход, пока
  все изменённые за сессию `.php`-файлы не пройдут `php -l`
- `.claude/agents/bitrix-reviewer.md` — сабагент для самопроверки диффа перед сдачей
- `.claude/agents/project-mapper.md` — сабагент, строящий и обновляющий карту
  кода проекта (`.claude/project-map.md`); модель — `sonnet` (сейчас это Sonnet 5)
- `.claude/hooks/check-project-map.sh` — при старте сессии проверяет, есть ли
  карта кода и не устарела ли она
- `.claude/hooks/check-claude-md-size.sh` — при завершении каждого хода
  проверяет размер `CLAUDE.md`, предупреждает, если больше ~200 строк
- `.claude/skills/bitrix-map/SKILL.md` — карта инфоблоков/HL-блоков/модулей
  **этого проекта**, подгружается по требованию
- `.claude/skills/1c-bitrix/` — общий справочник по платформе (D7 API,
  инфоблоки, компоненты, безопасность, магазин, интеграции), тоже
  подгружается по требованию — не путать с `bitrix-map`, это разные вещи
  (см. пояснение внутри `bitrix-map/SKILL.md`)
- `.gitattributes` — держит LF-переводы строк в хуках (важно для Windows,
  см. раздел ниже)

## 0. Если Claude Code ещё не установлен

macOS / Linux / WSL:
```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows (PowerShell):
```powershell
irm https://claude.ai/install.ps1 | iex
```

Проверка: `claude --version`. Нужен платный аккаунт (Pro/Max/Team/Enterprise
или Console) — на бесплатном плане claude.ai Claude Code недоступен.

## Если вы на Windows

Хуки в этом комплекте — bash-скрипты (`.sh`). Claude Code на Windows
запускает такие команды через **Git Bash** (устанавливается вместе с
[Git for Windows](https://git-scm.com/downloads/win)). Без него хуки
работать не будут — сам `claude` при этом запустится и без Git Bash, но
переключится на PowerShell как основную оболочку и bash-скрипты выполнять
не сможет.

- Проверить, что Git for Windows уже стоит: `git --version` в любом терминале.
- Права на исполнение (`chmod +x`) нужно выставлять именно в Git Bash —
  в PowerShell/CMD команды `chmod` попросту нет (правый клик по папке
  проекта → **Git Bash Here**, если пункт есть в меню — Git for Windows
  уже установлен).
- Если когда-нибудь будете редактировать `.sh`-файлы блокнотом/другим
  Windows-редактором — следите, чтобы переводы строк оставались LF, а не
  CRLF (иначе Git Bash не распознает первую строку скрипта). В комплект
  уже добавлен `.gitattributes`, который держит это автоматически, если
  проект под git.

## 1. Куда кладутся файлы

Всё копируется в корень Bitrix-проекта — туда же, где лежат папки `bitrix/`,
`local/`, `upload/`:

```text
my-bitrix-project/              ← корень проекта, отсюда вы запускаете `claude`
├── bitrix/                     ← ядро (уже было, не трогаем)
├── local/                      ← ваш код (уже было)
├── upload/                     ← (уже было)
├── CLAUDE.md                   ← НОВОЕ, из комплекта
└── .claude/                    ← НОВОЕ, из комплекта
    ├── settings.json
    ├── settings.local.json     ← не входит в комплект, создать самому (см. п.5)
    ├── hooks/
    │   ├── protect-core.sh
    │   ├── php-lint.sh
    │   ├── verify-before-stop.sh
    │   ├── check-project-map.sh
    │   └── check-claude-md-size.sh
    ├── agents/
    │   ├── bitrix-reviewer.md
    │   └── project-mapper.md
    ├── project-map.md            ← НЕ входит в комплект, создаётся сабагентом сам
    └── skills/
        ├── bitrix-map/
        │   └── SKILL.md          ← данные вашего проекта
        └── 1c-bitrix/
            ├── SKILL.md          ← общие знания платформы
            └── references/
                ├── admin-integration.md
                ├── components.md
                ├── d7-api.md
                ├── ecommerce.md
                ├── iblocks.md
                ├── security.md
                └── templates-frontend.md
```

## 2. Что где настраивается

| Что | Файл | Как активируется |
|---|---|---|
| Память о проекте | `CLAUDE.md` в корне | Просто лежит в корне — подхватывается автоматически при старте сессии из этой папки |
| Карта инфоблоков/HL-блоков (данные проекта) | `.claude/skills/bitrix-map/SKILL.md` | Автообнаружение по пути `.claude/skills/<имя>/SKILL.md` — регистрировать отдельно не нужно |
| Справочник по D7/безопасности/магазину (общие знания) | `.claude/skills/1c-bitrix/SKILL.md` + `references/*.md` | Та же автообнаружение; `SKILL.md` — короткий индекс, файлы из `references/` Claude читает сам по мере надобности |
| Права доступа (deny/allow) | `.claude/settings.json`, ключ `"permissions"` | Проверяется самим Claude Code перед каждым действием, а не моделью |
| Хуки — когда срабатывают | `.claude/settings.json`, ключ `"hooks"` | Здесь написано ЧТО за событие (PreToolUse/PostToolUse/Stop) запускает КАКОЙ файл |
| Хуки — что делают | `.claude/hooks/*.sh` | Сама логика проверки; файл должен быть исполняемым (`chmod +x`) |
| Сабагент-ревьюер | `.claude/agents/bitrix-reviewer.md` | Автообнаружение по пути `.claude/agents/*.md` — регистрировать отдельно не нужно |
| Сабагент — карта кода | `.claude/agents/project-mapper.md` | То же автообнаружение. Сам файл карты (`.claude/project-map.md`) не входит в комплект — создаётся сабагентом при первом запуске |
| Проверка карты кода при старте | `.claude/settings.json` → `"hooks"` → `SessionStart` **+** `.claude/hooks/check-project-map.sh` | Срабатывает в начале каждой сессии, молчит, если карта есть и актуальна |
| Контроль размера CLAUDE.md | `.claude/settings.json` → `"hooks"` → `Stop` **+** `.claude/hooks/check-claude-md-size.sh` | Срабатывает после каждого хода, молчит, если файл ≤200 строк |
| Личные настройки (не для команды) | `.claude/settings.local.json` (создайте сами) | Тот же формат, что и `settings.json`, но не должен идти в git |

Важно: `CLAUDE.md` Claude Code ищет, поднимаясь вверх по дереву папок от
текущей директории — сработает, даже если вы запустили `claude` из
подпапки. А вот `.claude/settings.json` (права и хуки) читается **только**
из той папки, откуда запущен `claude`, наверх не поднимается. Поэтому
всегда заходите в терминале именно в корень проекта перед запуском `claude`.

## 3. Установка по шагам

```bash
# 1. Распаковать архив и скопировать содержимое в корень проекта
cp -r claude-code-bitrix-kit/CLAUDE.md  /путь/к/my-bitrix-project/
cp -r claude-code-bitrix-kit/.claude    /путь/к/my-bitrix-project/

# 2. Сделать хуки исполняемыми — обязательный шаг,
#    права на выполнение не всегда переживают скачивание/архивацию
cd /путь/к/my-bitrix-project
chmod +x .claude/hooks/*.sh

# 3. Запустить Claude Code из КОРНЯ проекта
claude
```

При первом запуске откроется браузер для входа в аккаунт — это нужно
сделать один раз.

## 4. Что донастроить руками

- `CLAUDE.md` — впишите версию PHP/Битрикс, команды запуска стенда, свои
  конвенции кода (плейсхолдеры вида `` `<...>` ``)
- `.claude/skills/bitrix-map/SKILL.md` — впишите реальные ID инфоблоков и
  HL-блоков (можно один раз попросить Claude собрать их из админки/БД и
  сохранить в этот файл)
- `.claude/settings.json` → `permissions.allow` — добавляйте команды,
  которые считаете безопасными для своей команды (деплой, тесты и т.д.)
- `.claude/skills/1c-bitrix/` — донастраивать не нужно, это готовый общий
  справочник. Обновляйте только если у вас нестандартная версия платформы
  или свои соглашения, отличающиеся от описанных там

## 5. Проверка, что всё подключилось

Внутри запущенной сессии `claude`:

- `/context` — в списке **Memory files** должен быть `CLAUDE.md`
- `/hooks` — должны быть видны хуки на `PreToolUse`, `PostToolUse`, `Stop`, `SessionStart`
- `/memory` — список всех файлов памяти, можно открыть/отредактировать
- Написать в чат «используй bitrix-reviewer, чтобы проверить последние
  правки» — должен запуститься сабагент
- В самом начале сессии (или в `/context`) должно быть заметно сообщение
  о том, что карты кода нет — это нормально при первом запуске, значит
  хук `check-project-map.sh` сработал. Дальше можно явно попросить:
  «запусти project-mapper, построй карту кода»
- `claude doctor` (из обычного терминала, не внутри сессии) — общая
  диагностика конфигурации и хуков

## 6. Как работает карта кода (project-mapper)

Три части работают вместе:

1. **Хук `check-project-map.sh`** (`SessionStart`) — при каждом старте сессии
   молча проверяет: файл `.claude/project-map.md` существует? Если да —
   совпадает ли отметка `mapped-at-commit` в нём с текущим `git HEAD`?
   Если карты нет или коммит разошёлся — сообщает об этом Claude текстом
   в контекст. Ничего не решает сам, только информирует.
2. **CLAUDE.md** — говорит Claude, что делать с этой информацией: сначала
   вызвать `project-mapper`, потом браться за задачу.
3. **Сабагент `project-mapper`** — при первом запуске обходит `/local/` и
   строит карту с нуля. При последующих вызовах с конкретным запросом
   («найди, где обрабатывается X») — читает существующую карту, ищет
   именно недостающее, дописывает только это, не пересобирает всё заново.

Модель для сабагента — `sonnet` (alias). Сейчас это резолвится в Sonnet 5,
как вы и просили; если понадобится жёстко зафиксировать именно эту версию
независимо от будущих обновлений алиаса — замените `model: sonnet` на
`model: claude-sonnet-5` в `project-mapper.md`.

`.claude/project-map.md` в комплект не входит и не должен — его отсутствие
и есть условие первого запуска. Если создать пустой файл заранее, хук
решит, что карта уже есть, и подсказки не будет.

Без git отметка `mapped-at-commit` тоже будет работать (сабагент запишет
`no-git`), просто проверка «не устарела ли карта» отключится — хук молча
пропустит этот шаг, ошибок не будет.

## 7. Git: что коммитить, а что нет

Общее для команды (коммитим):
`CLAUDE.md`, `.claude/settings.json`, `.claude/hooks/`, `.claude/agents/`,
`.claude/skills/`, `.gitattributes`, `.gitignore`. Карту кода
`.claude/project-map.md`, когда она появится, — тоже стоит коммитить: это
общая для команды выгода, не личная настройка.

Личное, не для команды (уже в `.gitignore`):
`.claude/settings.local.json`, `CLAUDE.local.md` (если заведёте).

**`/bitrix` в этом комплекте не трекается вообще** — это стандартная
практика: ядро приходит от платформы, версионировать нужно только
`/local`. Если проект уже был закоммичен целиком до того, как вы поставили
этот `.gitignore`, добавление файла в `.gitignore` само по себе не уберёт
уже проиндексированные файлы — нужно ещё выполнить `git rm -r --cached bitrix/`
(файлы на диске не тронет, уберёт только из индекса git).

Если у вас кастомные шаблоны физически лежат в `/bitrix/templates/`, а не
в `/local/templates/` — прочитайте комментарий в самом `.gitignore`, там
есть замена на случай именно такой структуры.

## Куда двигаться дальше

- Если проект — набор из нескольких кастомных модулей, добавьте отдельный
  `CLAUDE.md` в каждый `/local/modules/<module>/` — Claude подхватит его
  именно при работе в этом модуле.
- Для больших инсталляций `/bitrix/` можно дополнительно включить sandboxing
  (изоляция на уровне ОС поверх правил permissions) — см. документацию Claude
  Code по sandboxing.
- Если у вас есть языковой сервер для PHP (Intelephense и т.п.), поищите
  готовый плагин "code intelligence" через `/plugin` — это снижает число
  файлов, которые Claude читает для навигации по коду.
